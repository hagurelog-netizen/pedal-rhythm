# pedal-rhythm

家庭用エアロバイクを、iPad の「リズムゲーム風ペースメーカー」で漕ぐためのウェブアプリを作る計画です。
いまは最初の一歩として、**バイクにつないで、どんな数字が届くかを確かめるページ**だけがあります(ゲーム本体はまだありません)。

対象のバイク: QLEE 第7世代フィットネスバイク(Zwift 連動)。送ってくるデータの種類と規格は公式情報で確認できていないため、まず実機で調べます。

## ゲーム(宇宙採掘)

公開 URL: `https://hagurelog-netizen.github.io/pedal-rhythm/game/`

漕ぐ速さで採掘船を左右に動かし、狙った小惑星を割って鉱石を持ち帰るゲームです。

- **レーン**: 遅い = 左(氷が多い)、基準 = 中央(鉄が多い)、速い = 右(結晶が多い)。レーンの幅は 8 rpm です。
- **採掘**: 前から 2〜3 個の小惑星が来ます。狙うレーンに合わせるとロックオンし、同じレーンで漕ぎ続けると割れます。
- **熱**: 右のレーンでは熱が溜まり、満タンで 6 秒止まります。氷を掘ると冷えます。
- **連鎖**: 割り続けると取れ高と音楽が増えます。ゆっくりのレーンを選んでも連鎖は続きます。
- **出来事**: 宇宙ゴミがレーンを 1 本ふさぐ、彗星が短い時間だけ来る、など。
- **ノブ**: 区間の始めに「ノブを回してみよう」と出ます。回したら「回した!」を押すと、その区間は取れ高 1.2 倍(自己申告)。
- **育てる**: 集めた鉱石で船を改造(冷却装置・ドリル・レーダー)。今日の依頼を達成すると拠点が増設されます。
- **時間と強さ**: 15 / 20 / 30 分、軽め / ふつう / しっかり(基準の回転数が変わるだけで、もらえる物は同じ)。
- 「バイクなしで試す」を選ぶと、スライダーで回転数を動かして遊べます。
- 記録はその端末のブラウザの中にだけ保存されます。拠点画面の下から、書き出しと読み込みができます。

## 接続テストのページでやること

- バイクに Bluetooth でつなぎ、見つかったサービスと characteristic を一覧表示する
- 通知(notify / indicate)を購読し、ケイデンス・速度・パワーを大きく表示する
  - FTMS の Indoor Bike Data、CSC Measurement、Cycling Power Measurement を解析します
  - どの規格から取れた値かも画面に出します
- 解析できない通知も含め、受け取ったデータを 16 進数のままログに残す(最新 300 件)
- バイクの設定を変える書き込みは一切しません(読み取りと通知の購読だけ)

## ユーザーが一度だけする設定

公開用の GitHub Actions はもう入っています。リポジトリ側で次の設定を **1 回だけ** してください。

1. GitHub のこのリポジトリを開く
2. **Settings → Pages** を開く
3. **Build and deployment** の **Source** を **「GitHub Actions」** にする

この設定をする前に `main` へマージすると、公開用のワークフローが失敗します。
その場合は設定後に **Actions → Deploy to GitHub Pages → Run workflow** を押せばやり直せます。

## iPad の Bluefy で試す手順

iPad の Safari は Web Bluetooth に対応していません。App Store の無料アプリ **「Bluefy – Web BLE Browser」** で開きます。

公開 URL: `https://hagurelog-netizen.github.io/pedal-rhythm/`
(Pages の設定後、`main` にマージされると約 1 分で公開されます。Settings → Pages にも URL が出ます)

1. App Store で「Bluefy – Web BLE Browser」をインストールする
2. バイクの電源を入れる(Zwift や他のアプリがバイクにつながっていたら、先に閉じる。同時に 2 つの機器からはつながらないことが多い)
3. Bluefy のアドレス欄に上の URL を入れて開く
4. **「バイクに接続」** を押す
5. 近くの Bluetooth 機器の一覧が出るので、バイクのものを選ぶ(名前が分からなければ、バイクを漕ぎながら出てくる名前を順に試す)
6. サービスの一覧が出て、ステータスが「接続中」になったら、ペダルを漕ぐ
7. 画面の **ケイデンス / 速度 / パワー** が動くか確かめる。負荷ノブを回して変わるかも見る
8. 次の 2 つを **スクリーンショット** で送る
   - 上から見たとき(数字と「取得元」の行、サービス一覧)
   - 下のログ欄(漕いでいる最中のもの)
   - 画面が長いので、スクロールして複数枚になっても構いません

「ログをコピー」を押すと、サービス一覧つきのログをクリップボードに入れられます(貼り付け先があれば)。

### うまくいかないとき

- 「Bluefy で開いてください」と出る → Safari など別のブラウザで開いています。Bluefy で開き直す
- 一覧にバイクが出ない → バイクの電源と、他のアプリが接続していないことを確認する
- 接続が切れた → 「再接続」を押す。だめなら「別のデバイスを選ぶ」
- 数字が出ない → その状態のログとスクリーンショットを送ってください。規格が分かれば次に進めます
- 漕いでいる途中で画面が暗くなる → iPad の設定 → 画面表示と明るさ → 自動ロックを「なし」にする(ページ側でも画面点灯を試みますが、Bluefy で効くかは未確認です)

## このページの限界

- 調べられるのは、あらかじめ指定したサービスだけです(FTMS 0x1826、CSC 0x1816、Cycling Power 0x1818、心拍 0x180D、Device Information 0x180A。見つけるための手がかりとして Generic Access / Generic Attribute / Battery と、独自サービスで使われがちな 0xFFF0 / 0xFFE0 も指定しています)。バイクがこれ以外の独自サービスでデータを送る場合、Web Bluetooth の仕様上このページには見えません。そのときは判明した UUID を追加します。
- CSC の速度はホイールの周長が必要です。画面の周長(初期値 2096 mm)は仮の値で、このバイクの実際の値ではありません。

## ファイル構成

- `public/index.html` … 接続テストページ本体(素の HTML/JS、ビルド不要)
- `public/game/index.html` … ゲーム本体(宇宙採掘。素の HTML/JS)
- `public/game/assets/` … ゲームの絵。決まった名前の画像を置くと、コードで描いた絵の代わりに使われる
- `docs/art/BRIEF.md` … 絵の制作依頼(画像生成で作る画像の一覧と条件)
- `.github/workflows/pages.yml` … `main` への push で `public/` を GitHub Pages に公開する

## パソコンで中身を確認するとき(開発者向け)

Web Bluetooth は HTTPS か `localhost` でしか動きません。

```bash
python3 -m http.server 8000 --directory public
```

Windows の Chrome / Edge で `http://localhost:8000/` を開くと、パソコン側の Bluetooth でも試せます(iPad では使えません)。
